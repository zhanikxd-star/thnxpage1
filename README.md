## Заявки в amoCRM

Обе формы — пошаговая перед видео и запись на консультацию (внизу страницы и во всплывающем окне) — отправляют заявку в `api/lead.php`. Этот PHP-файл создаёт в amoCRM (impact.amocrm.ru, API v4) сделку со связанным контактом:

- воронка «ПС (МЕНЕДЖЕРЫ)», первый этап после «Неразобранного» (воронка ищется по названию);
- контакт: имя — ФИО, телефон в стандартном поле «Телефон» с типом «Рабочий»;
- тег VSL, ответственный — владелец токена;
- примечание к сделке: какая форма, кто заполнил (родитель или ученик), класс, английский, оценки, адрес страницы, UTM-метки и время отправки.

Видео открывается сразу после формы и не ждёт ответа amoCRM. Форма консультации показывает «Заявка отправлена» только после ответа amoCRM, а при ошибке просит попробовать ещё раз.

Если amoCRM недоступна, заявка не теряется: она дописывается в файл `vls-lead-data/failed-leads.log` рядом с конфигом. Там же лежит лимит: не больше 5 заявок с одного IP за 10 минут. Скрытое поле-ловушка отсекает простых ботов.

### 1. Интеграция и долгосрочный токен

1. Войдите в impact.amocrm.ru под пользователем, который должен быть ответственным за новые заявки, с правами администратора.
2. Откройте amoМаркет (в старом интерфейсе: «Настройки» → «Интеграции»), нажмите «⋯» справа вверху → «Создать интеграцию» → «Внешняя интеграция».
3. Название — например, «Лендинг VSL». Отметьте доступ к данным аккаунта, сохраните.
4. В интеграции откройте вкладку «Ключи и доступы», в блоке «Долгосрочный токен» нажмите «Сгенерировать», выберите срок действия и сразу скопируйте токен.

Токен даёт полный доступ к CRM. Не отправляйте его в чатах и не кладите в git или в папку сайта.

### 2. Конфиг с токеном

1. Скопируйте `amocrm-config.example.php` в `amocrm-config.php`.
2. Вставьте токен в `'token'`. Остальное можно не трогать: поддомен `impact`, воронка «ПС (МЕНЕДЖЕРЫ)».
3. Если поиск воронки по названию не подходит, укажите `pipeline_id` и `status_id`. Чтобы назначать другого ответственного, укажите `responsible_user_id`.

Файл `amocrm-config.php` указан в `.gitignore` и в репозиторий не попадает.

### 3. Загрузка на хостинг PS.kz

1. Соберите сайт: `npm install`, затем `npm run build`. Появится папка `dist`.
2. В панели управления хостингом PS.kz выберите PHP 7.4 или новее с расширением curl. Обычно это настройка версии PHP для домена.
3. Откройте файловый менеджер PS.kz или подключитесь по FTP (например, FileZilla; доступы — в панели PS.kz).
4. Загрузите **содержимое** папки `dist` в `public_html` (или в корневую папку домена), не саму папку `dist`. В `public_html` должны оказаться `index.html`, `assets`, `api` и остальные файлы.
5. Проверьте, что загрузился скрытый файл `api/.htaccess`. В FileZilla включите «Сервер» → «Принудительно показывать скрытые файлы». Этот файл закрывает доступ ко всему в папке `api`, кроме `lead.php`.
6. Положите `amocrm-config.php` **над** `public_html`, не внутрь неё. Например, если сайт в `/home/USER/public_html`, конфиг — `/home/USER/amocrm-config.php`.

`lead.php` ищет конфиг в папке над корнем сайта и на уровень выше. Можно также задать путь переменной окружения `AMO_CONFIG`, а поддомен и токен — переменными `AMO_SUBDOMAIN` и `AMO_TOKEN`. Рядом с конфигом `lead.php` сам создаст папку `vls-lead-data`: ей нужны права на запись для PHP.

### 4. Проверка после загрузки

Пройдите форму перед видео и отправьте форму консультации. В amoCRM в воронке «ПС (МЕНЕДЖЕРЫ)» на первом этапе должны появиться две сделки с тегом VSL, контактом и примечанием.

Если сделок нет, посмотрите `vls-lead-data/failed-leads.log` рядом с конфигом. Там будет причина и сами заявки, чтобы внести их вручную.

Ответ `api/lead.php` в инструментах разработчика браузера (вкладка «Сеть»):

| Ответ | Что значит |
|---|---|
| `not_configured` | конфиг не найден или в нём нет токена |
| `crm` | amoCRM отказала: неверный токен, нет воронки или нет доступа |
| `rate_limited` | слишком много заявок с одного IP |
| `origin` | запрос пришёл не с адреса сайта; если у сайта несколько доменов, перечислите их в `allowed_origins` |

### Локальная проверка без настоящего токена

```bash
npm run build
php -S 127.0.0.1:8090 tools/amocrm-mock.php      # заглушка amoCRM
```

Во втором терминале создайте тестовый конфиг вне репозитория:

```php
<?php // /tmp/amocrm-config.php
return ['subdomain' => 'impact', 'base_url' => 'http://127.0.0.1:8090', 'token' => 'test-token'];
```

И запустите сайт:

```bash
AMO_CONFIG=/tmp/amocrm-config.php php -S 127.0.0.1:8080 -t dist
```

Откройте http://127.0.0.1:8080/. Запросы к заглушке пишутся в `/tmp/amocrm-mock.log`. Пока существует файл `/tmp/amocrm-mock.fail`, заглушка отвечает ошибкой.

Для режима разработки с горячей перезагрузкой: `VLS_API_PROXY=http://127.0.0.1:8080 npm run dev`.
